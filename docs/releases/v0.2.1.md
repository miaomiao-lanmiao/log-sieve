# Log Sieve v0.2.1

Date: 2026-11-09 (Asia/Shanghai). Maintenance release draft.

- Keep indented Python source inside its traceback when the source begins with
  words such as `error`/`warning` or contains a JSON-looking object. Such source
  stays with the exception. Timestamped text and JSON records still start a
  separate entry after an incomplete traceback, even when indented.
- Preserve JSON-line indentation during redaction so traceback context survives
  the redaction pass. Credential redaction still runs before report generation.
- Recognize message-free exception class names such as `ValueError` and `Warning` within tracebacks,
  including chained exceptions, while keeping following log events separate.

Existing CLI flags and JSON schema 1 remain compatible. Corrected traceback
boundaries can change incident counts for the affected inputs. Standalone Node
errors and the v0.2.0 Python traceback features are retained.

```sh
npm install --global ./log-sieve-cli-0.2.1.tgz --ignore-scripts
logsieve --version
```

Requires Node.js 22+. The release draft requires successful hosted CI. Diagnostic
recognition and redaction remain heuristic and incomplete; review reports before
sharing. No npm registry publication is performed by this maintenance workflow.
